`tests/fixtures/v1-core.ts` 仅保存 Git HEAD 中的原始 640 个 ID 与统计，不复制完整核心元数据。V2 首屏必须实际载入这 640 个网格，GLB 字节哈希必须保持一致。原核心中少量连接组织允许更正系统分类，但不得丢失 ID 或几何。

## 对齐验证方法

验收独立解析实际 GLB 的 POSITION AABB 和 node 层级变换，应用查看器公开的只读共享父变换，与每个已载入结构的世界包围盒逐坐标比较。所有资产的实际父变换必须相同，不能分别居中或按各自高度缩放。

另核对胸大肌和胸骨的实际纵向区域交叠及肌肉的整体人体范围。缓存源坐标框架中的未中心化 bounds 不等于 GLB 的实际 scene 坐标，不能混用两者判断错位。

3.0 补充部件使用相同原生毫米坐标，没有新增独立配准变换。头骨锚点中心/尺寸差 8.57/9.77 mm，右髋锚点差 16.51/14.49 mm；固定接受阈值为原生身高 1%（17.19 mm），再逐个检查部位和左右。10 个补充肌肉通过。该版本一致性检查不代表临床级表面贴合，版本重塑仍可能产生局部形状差异。

## 自动验收范围

保留 V1 5 项测试，包括桌面旋转/缩放/隐藏/隔离/撤销/透明度/多选/搜索/重置、全身头腿足实际网格点选、原五层与预设、手机单指旋转及双指捏合、核心加载失败重试。

新增 10 项测试：

1. 原 640 个 ID、真实网格与 GLB SHA 保留；首屏只请求核心，肌肉首次载入并缓存。
2. 懒加载肌肉搜索、聚焦、组织详情及真实 Raycaster 点选；原生 GLB 与世界坐标逐项比对。
3. 八系统、组织类型、真实神经/连接组织的独立操作与观察模式。
4. 透明外层不抢目标；优先系统与实际重叠命中列表切换。
5. 延迟资产加载时撤销保留原核心隐藏历史。
6. 延迟搜索加载期间重置胜出，旧结果不得在到达后重选或重新聚焦。
7. 可选资产下载失败后局部重试，核心继续可用。
8. 不可用资源清单的禁用、说明和无虚假搜索结果。
9. 手机八层抽屉、按需肌肉、真实单指触摸与无横向溢出。
10. 实际生产 `dist/` 在 `/bodyDemo/` 静态子路径下的模型加载和真实点选。

失败及不可用场景通过网络资源夹具模拟，不通过写入应用状态制造结果；产品实际神经覆盖由真实资产清单决定。

## 浏览器性能样本

来源：本地 `playwright-report/index.html` 中首个 V2 核心/缓存测试的 `v2-browser-performance` JSON 附件。环境为本地无头 Chrome、1440×1000、高清模式；测试启动参数允许软件 WebGL，且存在自动操作与统计调用负载。没有以此识别真实手机 GPU，也没有测 Android 或 iOS 真机。

| 样本字段 | 实际记录 |
| --- | --- |
| 已载入资产 | 2：核心与肌肉 |
| Draw Calls | 1,053 |
| 绘制三角面 | 849,402 |
| 资产加载累计 | 463.7 ms |
| 核心加载 | 277.3 ms |
| 肌肉加载 | 186.4 ms |
| CPU 提交耗时 | 14.33 ms |
| FPS 计数 | 2.92 |
| 采样时 idle | false |

这个样本采于切层及缓存验收期间，是一次浏览器计数，**不是连续运动帧率基准**，CPU 提交时间也不是 GPU 绘制时间。静止画面按需重绘，FPS 可能降至 0；没有持续提交帧时，0 不能用来判断画面卡顿。本轮未记录持续旋转的标准化帧率区间，不从该样本推导手机性能。
